# Direct MFSK IQ Decoder — Session 2 Handoff

**Completed:** 2026-07-26  
**Scope:** controlled-IQ fixture preparation

## Result

Session 2 establishes a repeatable, provenance-verified controlled fixture
matrix without cutting or modifying the received-IQ corpus.

The checked-in evidence now maps each fixture to its external artifact
directory, WAV/SigMF filenames, target decoder capability, expected hashes,
and previously established independent decode or waveform measurements. The
matrix covers MFSK32 text, MFSK64 text, MFSK64 8×4 grayscale p8, and MFSK64
8×4 color p8 with an independently defined RGB vector.

`mfsk-fixture-inventory` checks every WAV, SigMF data file, and SigMF metadata
file. It reports verified, missing, and hash-mismatch states as JSON. Missing
optional corpus data is discoverable without failing by default;
`--require-all` makes completeness mandatory, while any hash mismatch fails.

`tools/pi-generate-controlled-mfsk-fixtures.sh` provides the repeatable
generation path. It verifies the isolated pinned fldigi source commit,
generates all four cases, fetches their provenance, converts each WAV to
analytic SigMF using the repository virtualenv, and performs strict inventory.
Regenerated bytes remain candidates until they match or their evidence is
deliberately reviewed; the workflow never repins hashes automatically.

## Verified local inventory

All four fixtures and all twelve pinned artifacts were available on the
development machine. Every SHA-256 matched
`docs/mfsk_fixture_evidence.json`. No new controlled fixture was needed and no
received recording was cut.

## Test behavior

Unit coverage pins matrix membership and artifact roles, distinguishes
verified/missing/mismatch states, checks optional versus strict CLI behavior,
and rejects artifact path traversal. A corpus-backed test verifies every hash
when available and skips clearly with the `RADIOGRAM_MFSK_FIXTURES`
instruction when it is not.

## Unresolved decisions

- The current matrix uses p8 pictures. Narrow controlled p2 and p4 DSP cases
  remain Session 6 obligations; they are not needed for the MFSK32 text slice.
- The pinned fldigi source is tag v4.2.12 at commit
  `b0032cabb70dc670064ed7561b9a626010a5e4ae`, while the executable reports
  `fldigi 4.2.11`. Both identities remain retained as provenance.
- Regenerated ALSA-loopback WAV bytes may differ across host/audio-stack
  changes. Such output must not silently replace the accepted pins.
