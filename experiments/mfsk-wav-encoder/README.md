# Session 8 qualification workflow

This evidence workflow leaves the encoder and decoder implementation unchanged.
All experiments run through the managed wrappers on a network-capable surface.
The repository virtualenv owns local Python work; the Pi workflow creates an
isolated venv using already available system dependencies and installs the
candidate wheel without dependency downloads. Missing dependencies must be
resolved with the requester before proceeding.

1. Build the candidate wheel into `.local/session8/distribution` with the
   repository Python's `pip wheel --no-deps` in a Mac managed command.
2. Run `stage.py` through the Mac wrapper from the repository root. It records
   HEAD plus source hashes, copies the frozen matrix/oracle/schema and fixture,
   and writes `.local/pi-session8-run.sh` containing the exact transfer bundle.
3. Run `tools/pi-remote.sh .local/pi-session8-run.sh`. The command stages a
   fresh Pi directory and invokes `tools/pi-qualify-mfsk-encoder.sh`. Eight
   full WAVs are generated by the installed wheel and replayed once each,
   from BPSK31 with wide-search RxID enabled. No mapped-mode metadata, manual
   mode changes, or editorial silence are supplied. The frozen explicit
   silence and copied-audio parts remain in the mixed case.
4. On successful workflow completion, the managed log contains a gzip tar
   between `EVIDENCE_BASE64_BEGIN` and `EVIDENCE_BASE64_END`. Decode this into
   `.local/session8/evidence`. Preserve the authoritative `result.md` and the
   textual portion of the log as `execution.log`, then remove only that
   completed managed-session directory. Leave Pi evidence intact.
5. Run `evaluate.py .local/session8/evidence` through the Mac wrapper. It
   writes the qualification manifest and schema-validation report. It scores
   observed mode/carrier transitions, exact ordered caller text, generated
   picture announcements, image dimensions/pixels, independent frozen RSID
   PCM, copied PCM, silence, and frame coordinates. Coordinate corroboration
   uses the locally qualified segment planner; it is not independent waveform
   evidence. Receiver polling identifies the observed mode's standardized
   identifier but does not expose raw RSID detector words.
   An optional second argument selects a corrected reporting schema while
   retaining the original schema under `source/`; the selected schema is
   copied and hashed in the manifest. This is for failure representation,
   never for relaxing the matrix or its passing-case requirements.
6. Inspect every discrepancy before acceptance. A receiver exit code alone
   does not pass a case. Images with unequal pixels need measured differences
   and candidate-set visual review when exact evidence cannot settle the
   defect. Manual-window diagnostics can localize a failure but cannot change
   the full-WAV result into a pass. Keep remediation in Session 9.
   `review.py EVIDENCE_ROOT` creates the candidate-set review. Its local
   GramPy column uses known segment boundaries and carrier hints and is
   explicitly coupled diagnostic evidence. It cannot qualify a failed Pi
   case. A baseline placeholder is required because this new encoder has no
   accepted production-output baseline.

Artifacts include the installed distribution, candidate source hashes,
source fixture and audio recipe, WAVs and integer encoder coordinates,
adapter commands and hashes, receiver binary, start/end configuration,
continuous control logs, receiver resource metrics, decoded text, images,
and the manifest. The checked-in closeout identifies the retained artifact
set and its hashes. Do not overwrite archived reference qualification data.
